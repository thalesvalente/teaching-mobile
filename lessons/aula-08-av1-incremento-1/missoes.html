M1 · 15 minutos · 2,5 pontos

Preparar e conhecer o projeto

Primeiro abra o aplicativo e localize as funções. Não é preciso acertar todos os testes agora.

Ao concluir: aplicativo aberto, arquivos conhecidos e registro do processo preparado.

Passo a passo da missão5 etapas · 0 de 5 marcadas

  1. Encontre a pasta correta

    Faça: no VS Code, abra lessons/aula-08-av1-incremento-1/projeto. Ela contém package.json, src e scripts. No terminal dessa pasta execute uma linha por vez:

    Terminal · pasta projeto
    npm ci
npm run preflight

    Confira: deve aparecer Preflight OK. Se package.json não for encontrado, confira o diretório do terminal.

  2. Abra o aplicativo

    Faça: execute npm run web, mantenha o terminal aberto e acesse http://127.0.0.1:8088 no mesmo computador.

    Confira: aparece Atividades da escola, com registros fictícios, busca e filtros. Não é necessário Expo.

  3. Explore antes de editar

    Faça: busque praça, selecione uma categoria, use Abrir detalhes e Voltar à lista. Experimente os botões de carregamento e erro.

    Confira: observe o que funciona e o que parece incorreto. Há TODO intencionais para completar.

  4. Organize o trabalho coletivo

    Faça: abra src/equipe.mjs e localize resolver(input). Conheça também os quatro arquivos src/individual/aluno1.mjs até aluno4.mjs. Dividam a programação como preferirem, sem atrelar nomes aos números.

    Confira: todos sabem onde ficam as funções. Apesar dos nomes históricos da pasta e dos arquivos, as quatro tarefas pertencem à equipe e nenhuma tem nota individual.

  5. Faça o primeiro teste e prepare o registro

    Faça: em um segundo terminal na pasta projeto, execute npm run nota. Examine src/evidencias.json e leia o registro reflexivo.

    Confira: o terminal mostra OK, PENDENTE e uma estimativa coletiva. O starter deixa a declaração como undeclared e reflexão vazia. Registrem depois o que realmente fizeram, inclusive quando não usarem IA.

Dica: expliquem a um colega o que uma função recebe e devolve. Consultar apoio do Gemini.

M2 · 25 minutos · 2,0 pontos

Fazer as funções essenciais responderem

Trabalhe em src/equipe.mjs, corrigindo um TODO por vez.

Ao concluir: estados, busca, filtros e IDs testados sem modificar a coleção de entrada.

Passo a passo da missão5 etapas · 0 de 5 marcadas

  1. Encontre os comandos da função

    Faça: em resolver(input), identifique os casos estado, filtrar e chaves. A propriedade input.op escolhe a operação.

    Confira: você consegue apontar onde alterar a mensagem de estado, a busca e a identidade dos registros.

  2. Confira a prioridade dos estados

    Faça: no caso estado, respeite a ordem carregando → erro → base vazia → filtro sem resultados → pronto. Quando duas condições coexistem, prevalece a primeira.

    Confira: use Experimentar carregamento e Experimentar erro. O critério M2-1 verifica a prioridade.

  3. Combine busca, categoria e período

    Faça: no caso filtrar, combine as três condições. Normalize texto e consulta para desconsiderar acentos, maiúsculas e espaços nas pontas. Todas e Todos não restringem. Use novo array, sem alterar input.items.

    Confira: nos dados iniciais, busque praca, categoria Arte, período Manhã: aparece Fotografia da praça. Repita com PRAÇA e praça.

  4. Preserve a identidade dos registros

    Faça: no caso chaves, devolva o ID original como texto, não a posição do registro. O ID numérico 0 também é válido.

    Confira: reordenar ou filtrar a lista não deve trocar a identidade do item. O teste M2-4 usa IDs estáveis.

  5. Teste e revise uma pendência por vez

    Faça: salve, atualize o navegador e execute npm run nota. Leia M2-1 a M2-4 e revise somente o caso relacionado ao erro.

    Confira: M2-3 também exige preservar a entrada, mesmo quando a saída está correta. Não altere o teste para fabricar um resultado aprovado.

M3 · 35 minutos · 3,0 pontos

Integrar lista, detalhe e formulário

Continue em src/equipe.mjs, conectando os comportamentos do aplicativo.

Ao concluir: demonstre estados, retorno, validação e resumo com os testes executados.

Passo a passo da missão6 etapas · 0 de 6 marcadas

  1. Diferencie vazio de nenhum resultado

    Faça: em estado, base items:[] produz vazio; base com registros e filtered:[] produz sem-resultados.

    Confira: use Experimentar lista vazia e Restaurar dados. Faça depois uma busca inexistente: as mensagens devem diferir.

  2. Implemente a recuperação de erro

    Faça: no caso tentar, estado de erro deve devolver {status:'carregando',error:null}. Preserve os outros estados válidos.

    Confira: clique em Experimentar erro e Tentar novamente: o carregamento deve ser seguido da lista.

  3. Abra e volte mantendo o contexto

    Faça: em navegar, open abre detail com o ID escolhido; back volta a list e limpa só selectedId. Preserve query, category e period.

    Confira: busque praça, categoria Tecnologia, período Manhã; abra um registro e volte. Os filtros devem permanecer iguais.

  4. Valide o formulário com mensagens

    Faça: em validar, título e categoria são obrigatórios após remover espaços nas pontas. Limites: 80 caracteres no título, 40 na categoria. Devolva {valid,errors}, com erros por campo.

    Confira: Adicionar ao rascunho sem título deve informar Informe o título.. Com título e categoria válidos, aceite o cadastro. Teste os limites e não rejeite tudo indiscriminadamente.

  5. Confira o resumo acessível

    Faça: em resumo, conte registros do recorte e devolva {total,text}, sem depender de cores ou das barras.

    Confira: o número de cartões corresponde a n registro(s) no recorte.. Se não há resultados, o texto informa zero.

  6. Demonstre o percurso completo

    Faça: percorra busca → filtros → detalhe → voltar → formulário → resumo → erro → tentar novamente. Execute npm run nota e examine M3-1 a M3-6.

    Confira: explique a um colega o que mudou. Os testes verificam funções; a demonstração permite observar a integração visual.

M4 · 25 minutos · 2,5 pontos para a equipe

Revisar o trabalho da equipe e entregar

Trabalhem nas quatro tarefas. A distribuição do trabalho é livre, mas a avaliação é coletiva: um critério M4 só passa quando todas as tarefas passam os respectivos casos.

Ao concluir: tarefas testadas, registro verdadeiro, JSONL gerado e entrega iniciada. Sem recibo validado, a entrega não está confirmada.

Passo a passo da missão6 etapas · 0 de 6 marcadas

  1. Distribua as quatro tarefas

    Faça: conheçam src/individual/aluno1.mjs a aluno4.mjs e organizem a colaboração. Os nomes históricos dos arquivos não identificam pessoas. Não coloquem nomes no código.

    Confira: todos os quatro arquivos serão trabalhados, mesmo quando a equipe tiver menos de quatro participantes.

  2. Implemente os contratos das tarefas

    Faça: abra os quatro cartões abaixo. Leia entradas, saídas, limites e casos inválidos. Complete os TODO preservando export function resolver(input), sem import, rede, DOM ou dados pessoais.

    Confira: cada função devolve JSON válido imediatamente, sem alterar a entrada. Peça uma pista, não a solução completa, caso use o tutor.

  3. Teste o conjunto da equipe

    Faça: execute npm run nota. Não use a seleção parcial de arquivos: a candidata exige as quatro tarefas. Confira M4-1 a M4-5.

    Confira: aparece uma nota coletiva. Um critério M4 falha se qualquer tarefa falhar naquele aspecto; retirar um arquivo não pode aumentar a nota.

  4. Registre o processo real

    Faça: atualize src/evidencias.json conforme o guia de registro. Declare uso ou não uso de IA e uma reflexão verdadeira. Quando houver uso, registre missão, pedido, sugestão, alteração humana e teste em aiLog.

    Confira: a declaração corresponde ao log. Não uso mantém o log vazio, mas não dispensa reflexão. Ausência de informação fica pendente. Não incluam nomes, senhas, tokens ou conversas completas.

  5. Gere um pacote para o grupo

    Faça: na pasta projeto, execute npm run entrega. O arquivo fica em entrega/entrega-a08.jsonl. Guarde também a pasta do projeto.

    Confira: o terminal informa que o JSONL foi criado. O pacote contém fontes e evidências, mas não nomes dos participantes. Não edite o JSONL manualmente.

  6. Confira a equipe e o recebimento

    Faça: abra a ficha da Aula 08, importe o JSONL e informe somente equipe e nomes dos participantes. Após liberação docente, selecione Avaliar e enviar. Reenvios devem manter a composição completa; mudanças exigem o professor.

    Confira: guarde PDF e recibo validado. Sem recibo validado, não há confirmação. Se o servidor estiver pendente ou a rede falhar, guarde o pacote e o registro local, sem tratar isso como envio.

Quatro tarefas técnicas — uma nota da equipe

Tarefa 1 · Busca normalizada · src/individual/aluno1.mjs

{op:'normalizar',value:' PRAÇA '} deve devolver 'praca'. Texto só com espaços e valor numérico 123 devolvem texto vazio. Normalize acentos e maiúsculas. Acima de 200 caracteres, devolva texto vazio.

Salve e execute npm run nota.

Tarefa 2 · Estados · src/individual/aluno2.mjs

Com loading:false, error:null, base com registros e recorte vazio, devolva 'sem-resultados'. Base vazia produz 'vazio'; entrada inválida produz 'erro'. Carregamento válido precede erro. Arrays têm até 100 registros.

Salve e execute npm run nota.

Tarefa 3 · Formulário · src/individual/aluno3.mjs

{op:'validar',form:{title:'Oficina',category:'Arte'}} deve produzir {valid:true,errors:{}}. Título ou categoria em branco são inválidos. Limites após remover espaços: 80 e 40 caracteres. Use as mensagens especificadas no contrato.

Salve e execute npm run nota.

Tarefa 4 · ID estável · src/individual/aluno4.mjs

{op:'chave',item:{id:'r24'}} devolve 'r24'; ID numérico 0 devolve '0'. ID ausente, inválido, texto vazio ou acima de 80 caracteres devolve null. Não use posição da lista como ID.

Salve e execute npm run nota.

Dica: o envio é parte de M4, não uma quinta missão. A divisão do trabalho nunca cria notas individuais.

Registro do processo: com ou sem IA

Na candidata, M1-4 considera um registro verdadeiro do processo, não a obrigação de usar Gemini. Em src/evidencias.json, mantenha aiLog e aiUsage. O arquivo inicial é:

{
  "aiLog": [],
  "aiUsage": {"status": "undeclared", "reflection": ""}
}

used: houve ajuda real; registre ao menos uma interação no log e uma reflexão. not-used: mantenha log vazio e explique como o grupo trabalhou sem IA. undeclared: informação ainda pendente. Para pontuar, a reflexão tem de 20 a 400 caracteres. Não invente experiências nem inclua dados pessoais. Esta política aguarda aceite docente.

Uma entrada real do log usa mission (M1–M4), request, suggestion, humanChange e test. Os quatro textos têm até 400 caracteres; no máximo 20 entradas. Use somente o que aconteceu de fato.
