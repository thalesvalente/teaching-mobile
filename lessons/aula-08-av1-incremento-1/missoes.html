M1 · 15 minutos · 2,5 pontos

Preparar e conhecer o projeto

Primeiro faça o aplicativo abrir e descubra onde estão as funções. Não é preciso acertar os testes agora.

Ao concluir: O aplicativo abre, o grupo sabe quais arquivos vai editar e o processo foi preparado para registro.

Passo a passo da missão5 etapas · 0 de 5 marcadas

  1. Encontre a pasta correta

    Faça: No VS Code, abra a pasta lessons/aula-08-av1-incremento-1/projeto. Ela deve conter package.json, src e scripts. No terminal dessa pasta, execute npm ci e npm run preflight.

    Terminal · na pasta projeto
    npm ci
npm run preflight

    Confira: Procure a mensagem Preflight OK. Se aparecer “package.json não encontrado”, abra o terminal na pasta projeto.

  2. Abra o aplicativo no navegador

    Faça: No mesmo terminal, execute npm run web. Acesse http://127.0.0.1:8088 no próprio computador. Deixe o terminal aberto.

    Terminal · na pasta projeto
    npm run web

    Confira: Aparece a página Atividades da escola, com registros fictícios, busca e filtros.

  3. Explore antes de editar

    Faça: Digite praça no campo de busca, selecione uma categoria, clique em Abrir detalhes e depois em Voltar à lista. Experimente também os botões de carregamento e erro.

    Confira: Observe o que funciona e o que parece incorreto. Os erros iniciais são esperados: o projeto tem TODO para completar.

  4. Localize seu lugar na equipe

    Faça: No explorador de arquivos, abra src/equipe.mjs e veja os casos de resolver(input). Depois abra src/individual/aluno1.mjs até aluno4.mjs. Combinem quem ficará no slot 1, 2, 3 ou 4.

    Confira: Cada integrante sabe qual arquivo individual vai editar. Em equipes menores, use os slots escolhidos nos comandos nota e entrega.

  5. Faça um primeiro teste e prepare o registro

    Faça: Abra um segundo terminal na pasta projeto e execute npm run nota. Leia a diferença entre OK e PENDENTE. Examine src/evidencias.json: após usar o Gemini, registre uma síntese verdadeira do pedido, da pista, da sua alteração e do teste.

    Terminal · na pasta projeto
    npm run nota

    Confira: O comando mostra uma nota formativa. Se não usou IA, mantenha aiLog: []; não invente evidências para ganhar pontos.

Dica: Uma função recebe uma entrada e devolve uma saída. Encontre resolver(input) e explique isso a um colega. Ver ajuda do Gemini.

M2 · 25 minutos · 2,0 pontos

Fazer as funções essenciais responderem

Trabalhe em src/equipe.mjs. Corrija um TODO por vez e confira o efeito no aplicativo.

Ao concluir: Estados, busca, filtros e IDs funcionam nos testes públicos sem alterar os dados originais.

Passo a passo da missão5 etapas · 0 de 5 marcadas

  1. Encontre a função que recebe os comandos

    Faça: Abra src/equipe.mjs e localize resolver(input). A propriedade input.op determina qual caso será executado. Identifique estado, filtrar e chaves.

    Confira: Você consegue dizer qual caso corresponde à busca, à mensagem de carregamento e à identidade da lista.

  2. Confira a prioridade dos estados

    Faça: No caso 'estado', verifique a ordem: carregando → erro → base vazia → nenhum resultado do filtro → pronto. Se duas situações ocorrerem ao mesmo tempo, escolha a primeira dessa ordem.

    Confira: Clique em Experimentar carregamento e Experimentar erro no aplicativo. O teste formativo deve apontar o critério M2-1 quando estiver correto.

  3. Implemente busca e filtros juntos

    Faça: No caso 'filtrar', faça texto, categoria e período funcionarem juntos. Compare sem diferenças entre maiúsculas, espaços nas extremidades e acentos. Use um novo array com filter; não edite input.items. As opções Todas e Todos não restringem.

    Confira: Com os dados iniciais, busque praca, selecione Arte e Manhã: o recorte deve mostrar Fotografia da praça. Teste também PRAÇA e praça.

  4. Mantenha os IDs dos registros

    Faça: No caso 'chaves', use o ID original de cada registro, não o índice na lista. Um registro que muda de posição após filtrar continua com a mesma identidade. O ID numérico 0 também é válido.

    Confira: Ao mudar filtros, o ID não deve virar “posição 0” ou “posição 1”. O critério relacionado é M2-4.

  5. Rode os testes novamente

    Faça: Salve o arquivo, atualize o navegador e execute npm run nota em outro terminal. Confira M2-1 a M2-4. Se houver PENDENTE, leia o nome do critério e revise apenas o caso relacionado.

    Terminal · na pasta projeto
    npm run nota

    Confira: O código precisa passar pelos casos sem modificar a coleção de entrada. O critério M2-3 observa essa preservação.

Dica: Se os filtros falharem, observe a entrada e a saída de filtrar antes de pedir ao Gemini uma pista. Ver ajuda do Gemini.

M3 · 35 minutos · 3,0 pontos

Integrar lista, detalhe e formulário

Ainda em src/equipe.mjs, melhore os comportamentos que conectam as partes do aplicativo.

Ao concluir: Você consegue demonstrar estados, retorno, formulário e resumo com os testes rodando.

Passo a passo da missão6 etapas · 0 de 6 marcadas

  1. Diferencie lista vazia de filtro sem resultado

    Faça: No caso 'estado', se a base items estiver vazia, o estado é 'vazio'. Se ela tiver registros, mas filtered estiver vazio, o estado é 'sem-resultados'.

    Confira: Clique em Experimentar lista vazia e depois em Restaurar dados. Faça uma busca inexistente: as mensagens devem ser diferentes.

  2. Implemente a recuperação de erro

    Faça: No caso 'tentar', quando state.status for 'erro', devolva um novo estado {status:'carregando',error:null}. Preserve os outros estados válidos.

    Confira: Clique em Experimentar erro e depois em Tentar novamente. A página deve retornar ao carregamento e, em seguida, à lista.

  3. Abra um detalhe e volte sem perder o contexto

    Faça: No caso 'navegar', a ação 'open' abre 'detail' com o ID selecionado; 'back' volta a 'list' e limpa apenas selectedId. Preserve query, category e period.

    Confira: Busque praça, selecione Tecnologia e Manhã, abra um registro e clique em Voltar à lista. Os filtros devem continuar iguais.

  4. Valide o formulário e dê mensagens úteis

    Faça: No caso 'validar', title e category são obrigatórios após remover espaços nas pontas. Limites: 80 caracteres no título e 40 na categoria. Devolva {valid,errors} com mensagens por campo. Não aceite um formulário válido como erro.

    Confira: Clique em Adicionar ao rascunho com o título vazio; deve aparecer Informe o título.. Depois preencha um título e escolha uma categoria; o formulário deve ser aceito. Revise também entradas nos limites.

  5. Confira o resumo acessível

    Faça: No caso 'resumo', conte os registros do recorte atual e devolva {total,text}. O texto precisa funcionar sem depender da leitura das barras.

    Confira: Compare a quantidade de cartões com o texto n registro(s) no recorte.. Se o recorte tiver zero, o texto deve mostrar zero.

  6. Demonstre o percurso completo e teste

    Faça: Salve, atualize e percorra: busca → filtros → detalhe → voltar → formulário → resumo → erro → tentar novamente. Execute npm run nota e confira M3-1 a M3-6.

    Terminal · na pasta projeto
    npm run nota

    Confira: Explique a um colega o que mudou e qual erro o programa agora evita. O avaliador automático confere funções; a demonstração permite observar a integração visual.

Dica: Se o teste do formulário continuar pendente, experimente um caso válido e outro inválido antes de alterar a condição. Ver ajuda do Gemini.

M4 · 25 minutos · 2,5 pontos por pessoa

Resolver seu desafio e entregar

Cada pessoa resolve o próprio arquivo. A equipe gera um pacote JSONL e usa a ficha para a entrega.

Ao concluir: Funções individuais testadas, JSONL gerado e entrega iniciada na ficha. O recebimento só está confirmado com recibo válido.

Passo a passo da missão6 etapas · 0 de 6 marcadas

  1. Escolha o seu slot

    Faça: Combine um número de 1 a 4 por integrante. Abra somente seu arquivo src/individual/alunoN.mjs, correspondente ao número escolhido. Não coloque nomes pessoais no código.

    Confira: Cada pessoa sabe qual função resolver(input) será sua e trabalha sem sobrescrever a função do colega.

  2. Resolva o desafio do seu arquivo

    Faça: Abra abaixo apenas o cartão do seu slot. Leia a entrada, a saída esperada, um caso limite e um caso inválido. Complete o TODO preservando export function resolver(input) e sem fazer import.

    Confira: O arquivo devolve JSON válido imediatamente, não altera a entrada e trata os casos que serão verificados. Procure uma pista no guia do Gemini se necessário.

  3. Teste sua parte separadamente

    Faça: Execute npm run nota na pasta projeto. Se a equipe tiver menos de quatro pessoas, acrescente -- --slots=1,2 (exemplo de dupla). Confira as cinco verificações M4-1 a M4-5 do seu slot.

    Terminal · na pasta projeto
    npm run nota

    Confira: Todos os membros conseguem explicar seu próprio código. OK e PENDENTE ainda são resultados formativos.

  4. Registre a aprendizagem real

    Faça: Depois de utilizar o Gemini, atualize src/evidencias.json com os campos mission, request, suggestion, humanChange e test. Se não utilizou, mantenha aiLog: [].

    Confira: O registro descreve somente o que realmente aconteceu. Não inclua nomes, senhas, tokens, e-mails ou conversas completas.

  5. Gere o pacote sem editá-lo manualmente

    Faça: Execute npm run entrega ou, se a equipe tem menos integrantes, npm run entrega -- --slots=1,2. O arquivo ficará em projeto/entrega/entrega-a08.jsonl. Guarde também a pasta do projeto.

    Terminal · na pasta projeto
    npm run entrega

    Confira: O terminal informa que o JSONL foi criado. O arquivo contém fontes e evidências, mas não contém os nomes dos integrantes.

  6. Importe na ficha e confira o recebimento

    Faça: Abra a ficha da Aula 08, importe entrega-a08.jsonl, informe a equipe e os nomes dos slots ativos e selecione Avaliar e enviar quando o professor habilitar o servidor. Guarde PDF e recibo.

    Confira: Sem recibo validado, a entrega não está confirmada. Se o serviço ainda não estiver implantado ou a rede falhar, guarde JSONL e PDF local e consulte o professor.

Seu desafio: escolha somente seu slot

Slot 1 · Busca normalizada · src/individual/aluno1.mjs

O que implementar e como experimentar: {op:'normalizar',value:' PRAÇA '} deve resultar em 'praca'. Teste ' ' (vazio), 123 (inválido) e textos com acento. Limite máximo de 200 caracteres; acima disso, devolva texto vazio.

Depois: salve seu arquivo e execute npm run nota. A nota só será oficial após a verificação pelo servidor.

Slot 2 · Estados da lista · src/individual/aluno2.mjs

O que implementar e como experimentar: Para items com registros e filtered:[], a saída é 'sem-resultados'. Se items:[], é 'vazio'. Entrada inválida produz 'erro'; carregamento precede erro.

Depois: salve seu arquivo e execute npm run nota. A nota só será oficial após a verificação pelo servidor.

Slot 3 · Validação do formulário · src/individual/aluno3.mjs

O que implementar e como experimentar: {form:{title:'Oficina',category:'Arte'}} deve ser válido e não gerar erros. Título em branco é inválido. Confira os limites de 80 e 40 caracteres e as mensagens por campo.

Depois: salve seu arquivo e execute npm run nota. A nota só será oficial após a verificação pelo servidor.

Slot 4 · ID estável · src/individual/aluno4.mjs

O que implementar e como experimentar: {item:{id:'r24'}} deve devolver 'r24'. O ID numérico 0 deve produzir '0', não null. ID ausente, inválido ou texto acima de 80 caracteres devolve null.

Depois: salve seu arquivo e execute npm run nota. A nota só será oficial após a verificação pelo servidor.

Dica: O envio não é uma quinta missão avaliativa: é a conclusão operacional de M4. Ver ajuda do Gemini.
